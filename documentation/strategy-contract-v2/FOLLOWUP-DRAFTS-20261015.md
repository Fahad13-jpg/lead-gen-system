# Follow-up drafts and readiness — local/scratch

Prompt version strategy_v2.7 requests follow-up message parts as well as internal intents, using the existing closed fact/benefit/copy contract. The brief includes the campaign's first four follow-up steps. Claim references, opt-out, greeting, sender, CTA, benefit presence, URLs, prohibited claims and message lengths are validated. Routine weak-fit follow-ups are rejected. Existing saved v1/v2 plans remain readable; old intent-only responses are not silently given template messages.

Template mode produces explicitly labelled drafts for matching campaign steps. AI-mode drafts use only the parts supplied by the model; missing parts produce `message_missing`. Saved `artifacts.followup_drafts` contain subject/body, campaign step, delay, method and review status inside the plan hash. Sequence/channel mismatches require review and cannot silently acquire an execution delay. This does not rewrite existing approved plans.

`followup-readiness.cjs` is a pure decision helper over an explicitly supplied trusted snapshot. It is not an authentication or database adapter. Migration 022 provides the read-only database check using current org-scoped plan/approval/trust gates, the actual previous activity with the same plan hash, elapsed delay, sending window, replies/bounces/suppression and recorded stop reasons. Any existing record for the target step blocks a new attempt. Both return execution_authorized=false, even when due. A recorded provider acceptance proves acceptance only, not reading or delivery.
